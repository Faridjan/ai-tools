# БАЗИС-Мебельщик 11 - работа через скрипты

Пользователь НЕ хочет, чтобы Claude кликал в UI Базиса или жал горячие клавиши. Всё делается через JS-API Базиса и резидентный агент. Единственное действие пользователя - один раз запустить агента из меню Скрипты.

Скил работает только на этой машине. В claude.ai его не загружать: старая копия там уже путала правила.

Справочники (читать по мере надобности):
- `references/infrastructure.md` - пути, агент, bz.ps1, служебные файлы, отладка
- `references/coordinates.md` - оси, размеры панели, ориентация, текстура, роли деталей, блоки, секции
- `references/recipes.md` - готовые рецепты (высота изделия, полки, материал, кромка, новая панель, фурнитура, пазы, предпроизводственный аудит, спецификация, проверка, сохранение)
- `references/furniture-clearances.md` - точные зазоры, отступы, пазы, цоколи и конструктив по типам изделий (шкафы, купе, угловые, прихожие, комоды, ящики, тумбы, кухни, профиль Gola)
- `references/ldsp-production-rules.md` - производственные правила ЛДСП, раскроя, кромки, крепежа, присадки, сложной обработки (фрезеровка, гнутые панели, спилы под углом), фрагментов и подготовки к чертежам/ЧПУ
- `references/pitfalls.md` - известные грабли (движок, API, Базис 11.6, фрагменты и производство)
- `references/api-ref.md` - весь Script API (из официального bazis.d.ts). Примеры кода: `C:\Users\Jarvis\Documents\Bazis11\_claude\ref\BazisSoft-Scripts\`
- `scripts/README.md` - всё исполняемое: агент, lib.js, bz.ps1, генераторы чертежей, образцы команд cmd_*.js (`scripts/examples`), официальные примеры BazisSoft (`scripts/ref`) и установщик `scripts/install.ps1`

Скил ставится плагином `mebel` из `github.com/Faridjan/ai-tools`, плагин единственный источник скриптов и справочников. `Documents\Bazis11\_claude` это развёрнутая копия и файлы обмена с агентом, её можно удалить и вернуть установщиком. Скрипты править только в репозитории плагина. Как вносить правки, описано в скиле `ldsp-furniture-design` (абзац «Где лежат знания»).

Пути. Везде в скиле и справочниках папка Базиса записана как `C:\Users\Jarvis\Documents\Bazis11`, это машина автора. На другом компьютере вместо неё брать папку Базиса пользователя: по умолчанию `%USERPROFILE%\Documents\Bazis11`, иначе спросить и передать установщику `-Bazis <путь>`. Установщик сам заменит путь во всех скриптах при копировании. Требования: Windows, БАЗИС-Мебельщик 11, для чертежей и спецификации Python 3 (`py -3`).

## Протокол работы

0. Рабочая папка. Если нет `<папка Базиса>\_claude\bz.ps1` или версия в `_claude\plugin_version.txt` отличается от версии плагина, выполнить `powershell -NoProfile -ExecutionPolicy Bypass -File <папка скила>\scripts\install.ps1`. Если при этом обновился `Claude Agent.js`, попросить пользователя перезапустить агента из меню Скрипты.

1. Статус агента: `powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\Jarvis\Documents\Bazis11\_claude\bz.ps1 -Status`. Не запущен - попросить пользователя запустить (один клик: меню Скрипты -> Claude Agent). Самому ничего не кликать. В ответе `-Status` есть `CAPS` (agent, scheduler, lib, node, utf8, inspector) и строка `BAZIS responding`. Нужен `agent 3.1` со `scheduler timer` и `lib 4`: если `lib 3`, выполнить `BZ.reload()`. После любой правки `lib.js` прогнать `cmd_selftest.js`. Если запущен `loop` или `BAZIS responding=False` - предупредить пользователя не трогать окно Базиса (Windows может закрыть его как зависший), подробности в `references/pitfalls.md`.
2. Путь открытой модели и бэкап одной командой: `log(Action.ModelFilename); BZ.backup()` (копия в `_claude\<имя>_BACKUP_yyyyMMdd_HHmmss.b3d`). Бэкап копирует файл с диска, то есть последнее сохранённое состояние: несохранённых правок в нём нет. Если модель ни разу не сохранялась, бэкапа не будет, сказать об этом пользователю.
3. Дамп: `BZ.dump('dump.json'); log('n=' + Model.Count);` и читать `_claude\dump.json`. У каждой детали есть `role` (side_left, side_right, partition, shelf, top, bottom, back, facade, plinth, filler, drawer, other), `orient`, `butts`, `cuts`, `owner`, `uid`. Для секций: `BZ.sections()`, для материалов: `BZ.materials()`.
4. План по геометрии, не по индексам (индексы плавают, uid стабилен в рамках сессии). Перед построением/правкой сверить зазоры и отступы по `references/furniture-clearances.md`. Если задача неоднозначна или затрагивает конструктив (фальшпланки, видимый крепёж, формат листа, замену материалов) - показать пользователю цифры "было -> станет" до правки.
5. Команда в файл `_claude\cmd_<задача>.js`, выполнить `bz.ps1 -File <путь>`. Ответ: OK/ERROR, `log(...)`, `ret` (последнее выражение), список изменённых деталей `~ имя [path] было -> стало` (с полями mat, t, butts, tex, rename, если менялись они) и результат автопроверки `BZ.inspect()`.
6. Проверить: список `changed` и `inspect` в ответе, при необходимости повторный дамп. Если пришёл ERROR и строка `PARTIAL`, часть правок уже применена и зафиксирована: команду целиком не повторять, разобраться по `changed` и доделать или вернуть следующей командой.
7. Перед сдачей модели в раскрой/чертежи выполнить предпроизводственный аудит (рецепт в `references/recipes.md`): проверить объединение материалов и кромок (убрать «чужие» декоры от фрагментов и кромку с МДФ), дубли крепежа разных поставщиков, диаметры отверстий `Holes` под свёрла цеха (ловить d2 под саморезы и лишние отверстия под ручки), формат листа ЛДСП (`BZ.SHEET`) и расставить позиции (`Action.ArrangePositions(0, Model)`).
8. Файл модели на диск не сохранять без явной просьбы. Но несохранённые правки пропадут, если Базис закроется (так 14.09.2026 пропала фальшпланка), поэтому после серии правок предложить пользователю сохранить. С его согласия: `BZ.save()` (бэкап прошлого файла и сохранение в тот же файл).
9. Закончили - `bz.ps1 -Stop` (или пользователь жмёт Esc в Базисе).

## Жёсткие правила для команд

- Движок - Node.js 8.x: `let/const`, стрелки, шаблонные строки, `for..of`, классы, Map/Set, `require('fs')` работают. Только `lib.js` и `Claude Agent.js` держать в ASCII (их читает Базис как ANSI).
- Кириллица в командах разрешена, если `-Status` показывает `utf8: true`. Иначе `\uXXXX`.
- Команда выполняется через `vm.runInThisContext` внутри блока `{...}`: `let/const` живут только в этой команде, `var` и `function` становятся глобальными и остаются до перезапуска агента. Имена `BZ`, `log`, `V` не переопределять. Номер строки в ошибке реальный.
- Перед изменением объекта - `Undo.Changing(obj)` (все `BZ.*`-правки делают сами). Для блоков `Undo.RecursiveChanging`.
- Сдвиги только глобальные: `BZ.move` (внутри `TranslateGCS`). `PositionX/Y/Z` - локальные координаты владельца, внутри повёрнутого блока они врут.
- Повороты в градусах, не в радианах: `blk.RotateGCS(AxisY, 180)`, никаких `Math.PI` (14.09.2026: `Math.PI` дал 3° и перекос). Поворот идёт вокруг глобального начала координат, после него вернуть объект `BZ.move` по габариту деталей и проверить размер.
- Двигать блоками: `BZ.move(BZ.units(список), ...)`. Выборки `BZ.find`, `aboveY`, `inY`, `inBox` возвращают и детали внутри блоков крепежа, ящиков и дверей, а поштучный сдвиг разбирает такой блок. Фрагменты без настроенной эластичности не растягивать вслепую - полки, опоры и крепёж разъедутся.
- Материал и кромку ставить строкой, скопированной из модели (`BZ.materials()`) или из каталога базы материалов. В базе строка хранится как "Имя\rАртикул" или просто "Имя", если артикула нет. Есть ли материал в базе, скрипт проверить не может: опечатка даёт материал, которого не увидят раскрой и смета. После вставки сторонних фрагментов (ящики, короба) обязательно перекрасить их детали и кромки в материалы заказа, а с фасадов МДФ удалить кромку.
- Формат листа ЛДСП не принимать на веру: `BZ.check()` по умолчанию использует размер из названия материала или `BZ.SHEET` (`2800x2070` под Egger), а для плит `2750x1830` (Lamarty, Kronospan) `BZ.SHEET` нужно задать явно. В самом Базис-Раскрой предупреждать пользователя, если материал может попасть в группу «Прочие площадные материалы» с чужим форматом листа.
- Не применять булевы операции («Операции с телами») к рабочим мебельным панелям — деталь теряет свойства панели и выпадает из раскроя, сметы и документации.
- Фурнитура только реальная: модель позиции, которая есть в наличии в каталоге ДСП Центра (dspc.kz/catalog), а если там нет, на kaspi.kz (порядок проверки в `references/my-shop.md` скила ldsp-furniture-design), с артикулом в имени, и одна единица фурнитуры это один объект. Ставить готовым файлом из библиотеки (`find_library.ps1`): `.f3d` через `OpenFurniture(file).Mount(...)`, `.fr3d` проверенным способом через `OpenFurniture(file).MountBox(...)` с выравниванием по габариту деталей (`BZ.move`), рецепт в `references/recipes.md`. Собирать фурнитуру из панелей и профилей (`BZ.addBox`, `AddExtrusion`) нельзя. Модели нет в библиотеке - сначала искать готовую у производителей в сети и скачивать (пользователь разрешил 14.09.2026; ссылки и порядок в `bazis-library.md` скила ldsp-furniture-design, раздел "Добавлено 14.09.2026"), распаковывать в новую подпапку. Аналог другого бренда ставить открыто: в имени блока артикул к покупке и пометка, чья 3D-модель. Собирать по каталогу только если нигде нет, и после согласия. После установки любой скачанной фурнитуры или фрагмента проверять присадку (`o.Holes`, особенно смещение ответной планки 37 мм и отверстия d2) и лишние элементы (заглушки, ручки, ненужные стяжки).
- Объект, созданный в команде, до её конца не виден в `BZ.find`, `BZ.dump`, `BZ.pick`, `BZ.bounds` и имеет UID -1. Работать через ссылку, которую вернул `BZ.addBox`; искать такую деталь можно со следующей команды.
- `alert/confirm/prompt/Get*` отключены (`Action.Interactive=false`), не использовать.
- Если правилась `lib.js` - командой `BZ.reload()` (перезапуск агента не нужен). Если правился сам агент - перезапуск из меню.
- `bz.ps1 -Code` ломается на пробелах и знаках равно при вызове через вложенный powershell: всегда `-File` (или `-Stdin`).
- Агентом в каждый момент пользуется одна сессия Claude: команды идут через общие `cmd.js` и `result.json` и перетирают друг друга. Правки `lib.js` и `bz.ps1` действуют и на другие сессии, поэтому `lib.js` менять одной заменой файла после проверки синтаксиса.

## Хелперы lib.js v4 (глобальные внутри команд)

- Вывод: `log(...)`; файлы: `BZ.write/read/exists`, `BZ.writeJson`, `BZ.writeCsv(name, rows)` (BOM для Excel)
- Обход: `BZ.all()` (у элемента `anc` - блоки-владельцы), `BZ.panels()`, `BZ.dump(file?)`, `BZ.info(o,path)`, `BZ.bounds()`, `BZ.carcass()`, `BZ.zones()`, `BZ.sections()`, `BZ.sectionShelves(sec)`, `BZ.size(o)` -> [dx,dy,dz], `BZ.orient(o)`, `BZ.role(o)`, `BZ.blockKind(block)` -> fastener, drawer, door или null
- Служебное: `BZ.reload()` - перечитать lib.js в работающем агенте
- Поиск: `BZ.find(fn(o,path))`, `BZ.byName(re)`, `BZ.byUid(n)`, `BZ.pick(uid, [x0,x1,y0,y1,z0,z1])` (существующая деталь по uid с проверкой габарита, иначе ошибка), `BZ.byRole('shelf')`, `BZ.inY(y0,y1,tol)`, `BZ.aboveY(y)`, `BZ.belowY(y)`, `BZ.inBox(min,max)`, `BZ.selected()`, `BZ.units(objs)` - блоки для сдвига
- Правки: `BZ.move(objs,dx,dy,dz)`, `BZ.setHeight(o,h,keepTop)`, `BZ.setWidth(o,w,keepRight)`, `BZ.setDepth(o,d,keepFront)`, `BZ.spreadShelves(shelves,y0,y1,step?)` (целые мм, step 32 под полкодержатели), `BZ.setMaterial(objs,name,t?)`, `BZ.addButt(o,idx,mat,t,{width,sign,clip}?)` (ширина ленты по умолчанию `BZ.buttWidth(толщина)`, `ClipPanel` по умолчанию true), `BZ.visibleEdges(o,dist)`, `BZ.rename(objs,fn)`, `BZ.addBox('X'|'Y'|'Z', имя, [x0,x1,y0,y1,z0,z1], материал, t, текстура?)` - новая панель точно в габарит
- Контроль: `BZ.inspect(opts?)` -> {count, bazis, own, errors}: встроенный инспектор Базиса (из скрипта в 11.6 ничего не находит) плюс `BZ.check(opts?)` - пересечение панелей и деталь, которая не выходит из листа (`BZ.sheetOf(материал)`, `BZ.SHEET`); `BZ.snapshot()` / `BZ.diff(a,b)`, `BZ.spec('spec.csv')` -> строки спецификации, `BZ.materials()` -> {sheets, edges} с точными строками материалов, `BZ.backup()`, `BZ.save()`, `BZ.caps()`
- Панель: `BZ.panel(o)`, `BZ.butts(p)`, `BZ.cuts(p)`, `BZ.plastics(p)`, `BZ.userProps(o)`; `V(x,y,z)` = NewVector

## Типовые задачи

Подробно в `references/recipes.md`, `references/furniture-clearances.md` и `references/ldsp-production-rules.md`. Коротко:
- Высота изделия за счёт одной секции: сдвинуть всё выше границы (блоками, через `BZ.units`), укоротить сквозные стойки и стойки секции, не забыть про ХДФ, подложки, уголки и LED-профили.
- Равномерные полки: `BZ.spreadShelves(BZ.sectionShelves(sec), sec.y0, sec.y1)` в пределах секции (с `step=32` при привязке к системе 32), утапливать полки на 1 мм от лица.
- Материал и объединение: строку взять из `BZ.materials()` или каталога базы, затем `BZ.setMaterial(список, строка, 16)`; кромка на видимые торцы: `BZ.visibleEdges` + `BZ.addButt` (всегда с `ClipPanel = true`); с фасадов МДФ кромку удалить.
- Новая деталь: `BZ.addBox` по габариту с явной `TextureOrientation` для древесных декоров; существующую перед правкой найти `BZ.pick`.
- Фурнитура: модель производителя из библиотеки одним объектом (`Mount` для `.f3d`, `MountBox` + `BZ.move` для `.fr3d`), болванки не ставить, после установки проверять присадку `Holes`.
- Предпроизводственный аудит: проверить объединение материалов/кромок, дубли крепежа, диаметры отверстий (`d2` под саморез vs `d5x13` евровинт), формат листа и выполнить `Action.ArrangePositions(0, Model)` перед чертежами.
- Спецификация: `BZ.spec('spec.csv')` (группировка по имени, материалу, толщине, размерам и кромке) или `make-spec-xlsx.ps1`.
- Проверка модели: `BZ.inspect()`, агент делает её сам после каждой правки. Реально работают собственные проверки lib.js: пересечение панелей и деталь больше листа с учётом текстуры. Встроенный инспектор Базиса из скрипта ничего не находит, поэтому крепёж и наличие материала в базе скриптом не проверить: это пользователь смотрит в Базисе через Анализ модели.
- Крепёж скриптом не пересчитывается - предупредить, если в модели есть крепёж (`fastener: true` в дампе).
- Какой крепёж ставить (правило пользователя): во всех невидимых стыках евровинт (конфирмат KON 7x50) ради надёжности; эксцентрик со штоком и шкантом только там, где головка конфирмата вышла бы на видимую пласть (крышка сверху, наружная боковина, открытая ниша, фасад). Перед установкой проверить, с какой стороны будет видна головка.
