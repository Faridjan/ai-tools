## Изменить высоту изделия за счёт одной секции

Сделано для "Закладная спальня": 3047 -> 3030, нижняя секция -17, антресоль без изменений.
```js
const D = 17, TOP = 2434;                 // граница верхней секции - из дампа
// всё выше границы опустить: блоками и только то, что целиком выше границы
const units = BZ.units(BZ.aboveY(TOP));
const whole = units.filter(u => u.GabMin.y >= TOP - BZ.EPS);
const cross = units.filter(u => u.GabMin.y < TOP - BZ.EPS).map(u => u.Name);
if (cross.length) log('блоки пересекают границу, решать отдельно:', cross);
BZ.move(whole, 0, -D, 0);
for (const s of BZ.inY(0, 3047, 2)) BZ.setHeight(s, BZ.size(s)[1] - D);   // сквозные боковины
for (const s of BZ.inY(0, 2450, 2)) BZ.setHeight(s, 2450 - D);            // стойки нижней секции
for (const s of BZ.inY(66, 2434, 2)) BZ.setHeight(s, BZ.size(s)[1] - D);  // перегородки между дном и антресолью
log('size', BZ.bounds().size);
```
Цоколь, дно и полки внутри нетронутой зоны не трогать. Ответ агента покажет `changed` и `inspect`. Если список `cross` не пустой (дверь или крепёж через границу), показать его пользователю: такой блок нужно растягивать или переставлять отдельно.

Что `aboveY` и `inY` не ловят (14.09.2026, повтор 3047 -> 3030 после потери правок): задняя ХДФ укорачиваемой секции (иначе нахлёст с ХДФ антресоли, `inspect` это находит), подложки боковых фальшпланок, уголки под крышкой (`GabMax.y == старый низ крышки`, двигать через `BZ.units`), вертикальные экструзии вроде LED-профилей внутри блоков "Наполнение" (`BZ.setHeight` их не берёт: `Contour.Clear()` + `AddRectangle` с меньшим `Max.y`, `Build()`, вернуть на место по `GabMin`). Уже прикрученную к потолку верхнюю фальшпланку не двигать вместе с корпусом, а ставить на замер (`cmd_lower_3030*.js`).

Габаритная рамка модели (объект "Габаритная рамка", материал `~$$$ModelLimits`) меняется свойствами `Width/Height/Depth` плюс `Build()` (`cmd_frame_resize.js`). Удаление детали: `DeleteObject(o)` после `BZ.changing(o)`, агент показывает `del`.

## Равномерно расставить полки в секции

```js
const secs = BZ.sections();                          // сначала посмотреть список ячеек
const sec = secs.find(s => s.zone === 0 && s.x0 > 1900);   // нужная ячейка по цифрам
log('gap', BZ.spreadShelves(BZ.sectionShelves(sec), sec.y0, sec.y1));          // целые мм
// log('gap', BZ.spreadShelves(BZ.sectionShelves(sec), sec.y0, sec.y1, 32));   // по сетке 32 от низа ячейки
```
`sec.y0` это верх нижней горизонтали яруса, `sec.y1` низ верхней. Сетка `step` отсчитывается от `sec.y0`: если отверстия под полкодержатели в модели начинаются от другой базы, сверить по дампу. Проверено на временных полках: зона 0..1000, три полки 16 мм, шаг 32 дают 224, 480, 736.

## Материалы модели и массовая смена

```js
const m = BZ.materials();
log(m.sheets.map(s => s.name + ' | ' + s.code + ' | t=' + s.t + ' | x' + s.panels));
const target = m.sheets.find(s => /Гикори/.test(s.name) && s.t === 16);
if (!target) throw new Error('нужного материала в модели нет');
log('changed', BZ.setMaterial(BZ.byRole('shelf'), target.material, 16));
```
Строку материала берут из `BZ.materials()` (то, что уже стоит в модели) или из каталога базы (`find_library.ps1 -Kind material -Query <код>` скила ldsp-furniture-design). В базе она хранится как "Имя\rАртикул" или просто "Имя" без артикула. Есть ли материал в базе, скрипт проверить не может: опечатка даёт материал, которого не увидят раскрой и смета. Толщину менять только если материал реально другой толщины; геометрия соседей не пересчитывается.

## Кромка на видимые торцы

```js
const E = BZ.materials().edges.find(e => e.t === 0.4);   // кромка, уже стоящая в модели
if (!E) throw new Error('в модели нет кромки 0.4: строку взять из каталога базы');
let n = 0;
for (const o of BZ.panels()) {
  const p = BZ.panel(o); if (p.Butts.Count) continue;
  for (const i of BZ.visibleEdges(o, 5)) { BZ.addButt(o, i, E.material, E.t); n++; }
}
log('butts added', n);
```
`BZ.addButt` пишет через `Butts.Add()`, ставит ширину ленты `BZ.buttWidth(толщина панели)` (19 для 16 мм) и `ClipPanel = true`: без подрезки кромка увеличивает деталь на свою толщину (проверено: 700 стало 702), ломая соотношение готового и распиловочного размеров. В ответе агента кромка видна как `butts=` у изменённых деталей. Штатный путь Базиса - `p.AddButt(materialControl, i)` с материалом из `NewButtMaterialInput`, пример в `Scripts\Облицовка видимых.js`.

## Предпроизводственный аудит модели (перед раскроем и чертежами)

Полный аудит делает скил `model-review`. Он собирает данные модели одной командой и прогоняет все проверки, включая те, что раньше делались этим рецептом (чужие материалы и кромки, дубли крепежа, диаметры отверстий, формат листа):

```
powershell -NoProfile -ExecutionPolicy Bypass -File <плагин>\skills\model-review\scripts\review.ps1 -Mode handoff -Expect 1200x2400x600 -Hidden left,top,back,bottom
```

Отчёт: `_claude\review\review_report.md`, деталировка `cutlist.csv`, фурнитура `hardware.csv`. Формат листа для плит без размера в названии (Lamarty, Kronospan 2750x1830) задаётся в `review_rules.json`, ключ `sheet.by_material`.

Отверстия присадки принадлежат объектам фурнитуры, а не панелям: читать `o.Holes` у деталей крепежа и переводить `o.ToGlobal(h.Position)`. Прежний вариант этого рецепта читал `p.Holes` у панелей, ничего не находил и молча сообщал, что отверстий d2 нет.

Быстрый просмотр без полного ревью:

```js
const m = BZ.materials();
for (const s of m.sheets) log(`${s.name} [${s.code || '-'}] t=${s.t}: ${s.panels} дет.`);
for (const e of m.edges) log(`кромка ${e.name} [${e.code || '-'}] t=${e.t}: ${e.edges} торц.`);
const holes = new Map();
for (const it of BZ.all()) {
  const o = it.obj; if (o.List) continue;
  let H = null; try { H = o.Holes; } catch (e) { continue; }
  if (!H || !H.Count) continue;
  for (let j = 0; j < H.Count; j++) { const k = `d${BZ.r(H[j].Diameter)}x${BZ.r(H[j].Depth)}`; holes.set(k, (holes.get(k) || 0) + 1); }
}
for (const [k, v] of holes) log(`${k}: ${v} отв.`);
log('геометрия и формат листа:', BZ.check({ tol: 1 }));
```

## Анимация дверей и ящиков

Проверено 14.09.2026 (`cmd_doors_anim.js`). Существующую панель можно перенести в новый блок присвоением владельца: `const blk = AddBlock('Дверь ...'); door.Owner = blk;` (старый путь удаляется, объект появляется внутри блока, крепёж-фрагменты на панели остаются). Тип анимации `blk.AnimType = AnimationType.DoorLeft` (петли слева, значение 2) или `DoorRight` (3), `blk.DoorAngle = 110`. Ящики: `AnimationType.Box` (8). Остальные: `DoorFlap` откидная, `DoorLift` подъёмная, `SDoorLeft/SDoorRight` купе. Петли и толкатели в блок двери не класть, они остаются на стойках.

Анимацию ставить всегда, даже если о ней не просили (правило пользователя 23.11.2026, SKILL.md шаг 6а). Сторону двери определять по петлям (петли на левой стойке дают `DoorLeft`), угол брать по петле с запасом (петля 120° даёт 110).

Ящик, который выдвигается вбок, а не к лицу модели (ТВ-тумба 1570, 23.11.2026: «шкатулка» на Movento едет вправо вдоль X): `Box` двигает блок по его локальной оси +Z, поэтому оси блока надо повернуть. Проверено (`cmd_tv_anim.js`, `cmd_tv_anim_fix.js`):
```js
const before = parts.map(o => [o.GabMin.x, o.GabMin.y, o.GabMin.z]);   // запомнить габарит ДО
const bb = AddBlock('Ящик ... (выдвигается вправо)');
for (const p of parts) p.Owner = bb;                 // короб, его фасад и крепёж короба; направляющие и TIP-ON не класть
Undo.RecursiveChanging(bb);
bb.RotateGCS(AxisY, 90);                             // локальная +Z блока -> глобальная +X (проверка: bb.ToGlobal)
const l = BZ.list(bb);
for (let i = 0; i < l.Count; i++) { const o = l.Objects[i]; Undo.Changing(o);
  o.TranslateGCS(V(before[i][0] - o.GabMin.x, before[i][1] - o.GabMin.y, before[i][2] - o.GabMin.z)); }
bb.AnimType = AnimationType.Box;
```
При повороте блока ориентация деталей сохраняется, сбивается только положение. Обратный `o.RotateGCS(AxisY, -90)` уводит детали на сотни мм, поэтому возвращать их только `TranslateGCS` по запомненному габариту и сверять до 0 мм. Как анимация выглядит в окне Базиса, скриптом не проверить, это смотрит пользователь.

Что выяснилось после первой проверки пользователем (24.11.2026, ТВ-тумба 1570):
- Если пользователь оставил анимацию открытой, детали в модели стоят в открытом положении: дверь повёрнута, ящик сдвинут, `GabMin/GabMax` и размер модели «врут». Перед любой правкой закрыть: `Undo.RecursiveChanging(blk); blk.Build()` возвращает блок в закрытое положение.
- У `Box` ход задаёт `DoorAngle`, похоже, в процентах. Значение 75 по умолчанию дало 663 мм, и ящик отрывался от корпуса. Под Movento NL 500 поставлено 51 (около 450 мм). Это предположение, сверить с пользователем после анимации. `DoorShift` (18) на положение не влиял.
- Петли и пластины TIP-ON, которые висят на двери, должны лежать в блоке двери, иначе чашки остаются в воздухе. Переносить можно только блоки верхнего уровня целиком (`hingeBlock.Owner = doorBlock`, координаты не меняются). Если перенести так деталь из глубины блока крепежа (чашку без планки), она уезжает и разворачивается: у блоков крепежа свои локальные оси. Вернуть её можно присвоением прежнего владельца.

## Паз в панели (фрезеровка под LED-ленту, ХДФ)

Проверено 14.09.2026 (`cmd_led_groove.js`, полка над ящиками). Паз это свойство панели, а не отдельный объект: попадает в чертёж детали и ЧПУ, `BZ.cuts(p)` его показывает, дамп пишет в `cuts`.
```js
const sh = BZ.pick(uid, [null, null, 884, 900, 5, 592]), p = BZ.panel(sh);
const o0 = sh.ToGlobal(V(0, 0, 0)), oT = sh.ToGlobal(V(0, 0, p.Thickness));
const zUp = oT.y > o0.y;                          // пласть локального z=0 нижняя, если локальная z растёт вверх
const A = sh.ToObject(V(x0, 884, 576)), B = sh.ToObject(V(x1, 884, 576));   // концы паза в локальных координатах контура
BZ.changing(sh);
const cut = p.AddCut('Паз под LED-ленту 12x5, нижняя пласть');
cut.Trajectory.AddLine(A.x, A.y, B.x, B.y);       // траектория в плоскости контура
if (zUp) cut.Contour.AddRectangle(-6, 0, 6, 5); else cut.Contour.AddRectangle(-6, p.Thickness - 5, 6, p.Thickness);  // профиль: x поперёк паза, y по толщине
cut.Sign = 'LED 12x5'; sh.Build();
```
Паз в пласти вертикальной стойки под LED-ленту (`cmd_led_grooves_walls.js`): та же схема, пласть выбирается сравнением `ToGlobal(V(0,0,0)).x` и `ToGlobal(V(0,0,T)).x` с x нужной пласти, траектория `ToObject(V(xПласти, y0, zЦентр))`..`ToObject(V(xПласти, y1, zЦентр))`.

Локальные оси у горизонтальной полки: x вдоль ширины, y вдоль глубины со знаком минус от начала контура (у полки 5..592 начало на z=37, глубина 576 дала y=-539), z по толщине от нижней пласти. Всегда проверять `ToGlobal` перед тем, как строить паз.

## Проверка модели

```js
const r = BZ.inspect();              // {count, bazis, own, errors}: bazis в 11.6 всегда 0, own - собственные проверки
const own = BZ.check({ tol: 1 });    // только собственные: SheetSize и Overlap
// Формат листа по умолчанию (если в имени материала нет размера плиты):
// Egger:   BZ.SHEET = { len: 2800, wid: 2070, trim: 10 };
// Lamarty: BZ.SHEET = { len: 2750, wid: 1830, trim: 10 };
r;
```
Агент сам делает `BZ.inspect()` после каждой команды, которая изменила модель. `SheetSize`: контур детали не выходит из листа с обпилом; размер листа берётся из названия материала ("2800*2070*16 мм"), иначе `BZ.SHEET` (`2800x2070` по умолчанию), направление текстуры учитывается (Horizontal вдоль `ContourWidth`, Vertical вдоль `ContourHeight`, None можно повернуть). `Overlap`: две прямоугольные панели заходят друг в друга глубже `tol` по всем трём осям; детали внутри крепежа и непрямоугольные детали не проверяются. Крепёж и наличие материала в базе скриптом не проверить: встроенный инспектор Базиса из скрипта ничего не находит, это пользователь смотрит в Базисе через Анализ модели. Отключить автопроверку на одну команду: `bz.ps1 -NoInspect`, насовсем в сессии: `BZ.autoInspect = false`.
