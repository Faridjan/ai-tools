# Система координат, размеры, роли

## Оси

- X - ширина (вправо), Y - высота (вверх), Z - глубина. Пол y=0.
- Всегда работать с `GabMin/GabMax` (глобальный габарит). `GMin/GMax/GSize` - локальные, `PositionX/Y/Z` - позиция в ЛСК владельца (внутри блока не совпадает с глобальной).
- Глобальный сдвиг: `obj.TranslateGCS(V(dx,dy,dz))` (это делает `BZ.move`). Поворот: `RotateGCS(axis, angle)`.
- Преобразования точек: `obj.ToGlobal(p)`, `obj.ToObject(p)`, нормалей `NToGlobal/NToObject`.

## Панель

- `ContourWidth x ContourHeight x Thickness`. У вертикальной стойки ContourHeight = высота по Y, ContourWidth = глубина. У горизонтальной полки ContourWidth = ширина по X, ContourHeight = глубина по Z. `BZ._resize` сам определяет, какая сторона контура лежит на нужной глобальной оси, сравнивая длины.
- `BZ.orient(o)` - ось толщины: `'X'` боковина/стойка/перегородка, `'Y'` полка/дно/крышка, `'Z'` задняя/фасад/цоколь.
- Подпись в дереве "2450x595x16" = ContourHeight x ContourWidth x Thickness для стоек. Дерево в UI после скриптовых правок подписи не обновляет - верить дампу.
- "Габаритная рамка" - служебный объект (ниша), не деталь; в высоту изделия не входит. `BZ.bounds()` считает габарит только по панелям, `Model.GSize` включает всё.
- Контур: `p.Contour.Count` элементов, индекс элемента = индекс торца для кромки (`AddButt(mat, idx)`, `IsButtVisible(idx, dist)`). `p.IsContourRectangle` - прямоугольная ли деталь.
- `TextureOrientation`: None 0, Horizontal 1, Vertical 2 (глобальное перечисление, есть и старые `ftoHorizontal`/`ftoVertical`). По данным модели (14.09.2026) Horizontal идёт вдоль `ContourWidth`, Vertical вдоль `ContourHeight`: у стоек, боковин и фасадов стоит Vertical, у полок Horizontal, у ХДФ и части планок None.
- Новая панель точно в габарит: `BZ.addBox('X'|'Y'|'Z', имя, [x0,x1,y0,y1,z0,z1], материал, t, текстура?)`. Внутри `AddVertPanel` (X), `AddHorizPanel` (Y), `AddFrontPanel` (Z), затем сдвиг в заданный угол и проверка размера.
- Объект, созданный в команде, до её конца не виден в обходе модели: `Model.Count` не растёт, `BZ.find`, `BZ.dump`, `BZ.pick` его не находят, `UID` равен -1. Работать через ссылку, которую вернул `addBox`; искать деталь можно со следующей команды, после фиксации агентом UID становится обычным. Удаление (`DeleteObject`) видно в обходе сразу.

## Роли (`BZ.role`)

Сначала блок-владелец, потом имя детали (без учёта регистра), потом геометрия.

| блок-владелец | role |
|---|---|
| блок крепежа (`IsFastener`) | other |
| блок ящика: `AnimType` Box или слово "ящик"/"ящика" в имени блока | drawer |
| блок двери: `AnimType` двери или имя блока начинается с "дверь"/"фасад" | facade |

Перечисление `AnimationType` в Базисе 11.6 есть (проверено 14.09.2026): Box = 8, двери DoorLeft 2, DoorRight 3, DoorFlap 4, DoorLift 5, SDoorLeft 6, SDoorRight 7. Имена блоков работают как запасной признак.

| имя детали содержит | role |
|---|---|
| слово "ящик" или "ящика" ("полка над ящиком" не считается) | drawer |
| цокол | plinth |
| заглушк, планк, фальш | filler |
| задн, двп, хдф | back |
| полк | shelf (раньше двери, так что "4 дверь полка" это полка) |
| дно (отдельным словом) | bottom |
| крыш | top |
| фасад, двер | facade |
| боковин | side_left / side_right |
| стойк, перегород (orient X) | side_left / side_right у края корпуса, иначе partition |

Геометрия, если имя ничего не дало:

| role | признак |
|---|---|
| filler | orient X, глубина меньше половины самой глубокой стойки |
| side_left / side_right | orient X у левого/правого края корпуса |
| partition | orient X внутри |
| top | orient Y, верх совпадает с верхом габарита |
| bottom | orient Y, низ в пределах 150 мм от пола |
| shelf | остальные orient Y |
| back | orient Z, толщина <= 6 мм |
| plinth | orient Z, высота <= 200 и у пола |
| facade | orient Z на передней или задней плоскости |

Край корпуса (`BZ.carcass()`) считается только по стойкам глубиной не меньше половины максимальной, поэтому узкие заглушки его не сдвигают. Роли - подсказка: у нестандартных изделий сверять по цифрам.

## Ярусы и секции

- `BZ.zones()` - ярусы по высоте между горизонталями корпуса (роли top/bottom), промежутки больше 100 мм. Например, нижний шкаф и антресоль. Дно ящика (роль drawer) ярус не создаёт.
- `BZ.sections()` - для каждого яруса стойки, перекрывающие ярус целиком (допуск 20 мм), соседние пары дают ячейку `{zone, y0, y1, h, x0, x1, w, left, right, shelves:[y...]}`.
- `BZ.sectionShelves(sec)` - объекты полок ячейки.
- Ограничение: ярусы общие по всей ширине. Если модули рядом разной высоты, ячейки проверять по цифрам.

## Блоки и крепёж

- `o.List` - структурный объект (блок/сборка), дети в `BZ.list(o).Objects`. `BZ.isFastener(o)` - блок крепежа. `BZ.blockKind(b)` - fastener, drawer, door или null.
- `BZ.all()` у каждого элемента хранит `anc` - цепочку блоков-владельцев от верхнего к ближнему.
- `BZ.units(objs)` заменяет детали внутри блоков крепежа, ящиков и дверей на внешний такой блок и убирает дубли. Сдвиги делать по нему. Дверь для `units` определяется только по `AnimType`, по имени нет: иначе группа "Фасады" стала бы одним блоком.
- `panel.FindConnectedFasteners()` - крепёж на панели, `fast.FindFastenedObjects()` - что он соединяет.
- Крепёж после сдвига панелей не пересчитывается. Встроенный инспектор Базиса из скрипта ошибок крепежа не показывает (проверено 14.09.2026), поэтому после таких правок пользователь смотрит Анализ модели в Базисе.
