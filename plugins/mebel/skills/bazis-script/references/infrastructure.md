## Программа

- Базис: `C:\Program Files (x86)\BazisSoft\Bazis 11\Bazis.exe`, версия 11.6.0.29897 (сборка сентябрь 2020), `system.apiVersion = 1101`.
- Скрипты исполняет встроенный Node.js 8.x (`node.dll` и `node_activex.node` в папке программы). Отсюда ES2015+, `require('fs'/'path'/'vm')`. Официальные примеры BazisSoft для Базис 10+ сами используют `let`, шаблонные строки и `fs`.

- Отдельного node.exe на машине нет. Синтаксис ES5-файлов (`lib.js`, агент) без Базиса проверяется через Windows Script Host: исходник подать на stdin cscript-скрипту, который делает `new Function(src)`. Пути длиннее 260 символов cscript не открывает, поэтому именно через stdin.

## Агент (v3, неблокирующий)

При старте: `system.require(lib.js)`, экспорт `BZ/log/V` в `global`, `Action.Interactive = false`, пишет `status.json` с `caps` (lib, node, fs, vm, es6, utf8, inspector, mode, agent, scheduler).

Планировщик: `setInterval(tick, 250)` и `Action.Continue()`, окно Базиса между тиками свободно. Если `setInterval` нет - цепочка `Action.AsyncExec`. Ошибки самого тика пишутся в `agent_error.json`. Esc в Базисе ловится через `Action.OnFinish`.

Запасной `_claude\agent-loop-fallback.js` (v2.1, в меню Скрипты его нет, запускать файлом вручную) крутит блокирующий цикл: использовать только если у v3 нет heartbeat, окно Базиса при нём не трогать (Windows закроет программу как зависшую).

Тик: читает `cmd.js` (UTF-8 через fs), id команды из `cmd.id`, выполняет через `vm.runInThisContext('{' + src + '}', {filename:'cmd.js'})` (fallback `eval`), делает `Action.Commit()` (и после ошибки тоже, так что частичные правки фиксируются), сравнивает снимок модели до и после (`BZ.snapshot/diff`: габарит, имя, материал, толщина, кромка, текстура), при изменениях запускает `BZ.inspect()` (собственные проверки lib.js: пересечения и деталь больше листа), пишет `result.json`:
`{id, ok, ret, log[], error, line, stack, changedCount, changed[], inspect{count, bazis, own, errors[]}, ms, modelSize}`.

Heartbeat каждые 2 с в `heartbeat.json`. Останов: `stop.flag` = 1, или Esc в Базисе, или 90 мин простоя.

## bz.ps1

```
bz.ps1 -Status            жив ли агент + CAPS
bz.ps1 -File cmd_x.js     выполнить файл (UTF-8 ок при caps.utf8)
bz.ps1 -Stdin             код из stdin
bz.ps1 -Code "..."        инлайн (только для коротких ASCII-строк без = и пробелов при вызове через вложенный powershell)
bz.ps1 -Raw               сырой result.json
bz.ps1 -NoInspect         не запускать автопроверку после этой команды (долгие массовые правки)
bz.ps1 -Stop              остановить агента
bz.ps1 -TimeoutSec 300    ждать дольше
```
Коды возврата (v3): 0 успех, 1 нет файла или пустая команда, 2 агент не запущен, 3 агент без UTF-8, 4 агент умер во время команды, 5 таймаут, 6 команда упала (ERROR), 7 агент дольше таймаута занят командой другой сессии. Команды разных сессий встают в очередь через именованный мьютекс `ClaudeBazisAgentCommand`, `cmd.js` пишется через временный файл и переименование.
Вызов всегда: `powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\Jarvis\Documents\Bazis11\_claude\bz.ps1 ...`

В сводке у изменённой детали кроме габарита печатаются `rename`, `mat`, `t`, `butts`, `tex`, если менялись они. Строка `PARTIAL` значит: команда упала, но часть правок уже зафиксирована. Windows PowerShell 5.1 при `ConvertTo-Json` превращает кириллицу в `\uXXXX`, поэтому строка `ret:` с кириллицей нечитаема: читать `result.json` через `ConvertFrom-Json` и печатать поля.

## Отладка

- `-Raw` показывает error, line (реальная строка cmd-файла), stack.
- `heartbeat.json` старше 6 с и без поля `busy` - агент умер, просить пользователя перезапустить из меню. Во время команды агент не может обновлять heartbeat (команда занимает поток), поэтому агент 3.2 перед запуском пишет туда `busy: <id команды>`, и `bz.ps1` ждёт, пока жив процесс Базиса. До 3.2 любая команда дольше 6 с давала ложное «agent died while running the command».
- Команда вернула объект Базиса или структуру со ссылкой на себя: в `ret` придёт `[circular]` или `[depth]`, раньше `result.json` не записывался и `bz.ps1` ждал до таймаута.
- Тесты без Базиса: `py -3 -m unittest discover -s plugins/mebel/tests` в репозитории плагина (макет API, настоящий агент в Node, настоящий `bz.ps1`). Они проверяют логику скриптов и протокол обмена, поведение настоящего API они не доказывают.
- Лёгкие подтормаживания UI Базиса при работе агента ожидаемы. Если окно не отвечает, это уже проблема: см. `pitfalls.md`.
- Если `CAPS` в статусе нет или `utf8: false` - запущен старый агент, попросить перезапустить.
- Проверка движка вручную: `bz.ps1 -File _claude\probe.js`, результат в `probe_result.json`.
- Самотест всего стека после обновления агента или lib.js: `bz.ps1 -File _claude\cmd_selftest.js`. Проверяет кириллицу, дамп, роли, секции, материалы, `BZ.units`, пустой diff снимка, спецификацию, автопроверку и обратимый сдвиг полки на 5 мм (если в модели есть роль shelf).
- Агент v3.1 и lib.js v3 проверены вживую 13.09.2026: таймер срабатывает примерно 4 раза в секунду, Базис отвечает, самотест, роли, ярусы и секции на "Закладной спальне" верные.
- lib.js v4 проверен вживую 14.09.2026 на "Закладной спальне" (51 объект, блоков нет):
  - `cmd_verify_v4.js`: роли, ярусы и 8 секций совпали с v3; `pick` находит деталь и отказывает при неверном габарите; `addBox` X/Y/Z ставит точно в габарит; `spreadShelves` со step 32 даёт 224, 480, 736; у объектов внутри команды UID -1;
  - `cmd_check_own_*`: `BZ.check` ловит пересечение 8 мм и панель 3000 мм; `addButt` ставит ширину 19 и `ClipPanel` true, размер панели сохраняется;
  - `cmd_selftest.js` без ошибок; на модели собственная проверка нашла цоколь "ШС - Цоколь видимый" 2532x86 с текстурой Vertical, то есть рисунок поперёк длины;
  - встроенный инспектор Базиса из скрипта не нашёл ничего даже на заведомых ошибках (см. `pitfalls.md`).

- Если агент молчит, смотреть `AGENT_TRACE` в `-Status` (журнал шагов запуска `_claude\agent_trace.txt`): последний записанный шаг показывает, где он остановился. Ошибки старта в `agent_error.json`.
