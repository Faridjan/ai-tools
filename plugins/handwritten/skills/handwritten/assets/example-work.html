Откуда приходит заказ

Заказ создаётся с сайта, из приложения или повтором из корзины. Все три пути идут в один вызов POST /orders, и он:

  • проверяет корзину и цены
  • резервирует товар на складе
  • запоминает ключ идемпотентности: второй клик не создаёт второй заказ

двойной клик по "Купить" чинили в SHOP-412

Три очереди

Тяжёлая работа уходит в RabbitMQ. Очередь выбирается по срочности, каждую разбирают свои воркеры.

orders-hot | покупатель ждёт на странице orders-retry | повтор после сбоя оплаты orders-bulk | импорт оптовых заказов

воркеров добавляет HPA по длине очереди

Один клик - один заказ

Сеть рвётся, покупатель жмёт ещё раз. Ключ идемпотентности превращает повтор в безопасную операцию.

второй заказ | тот же заказ дважды | один раз

Резерв на 15 минут

Товар держим за покупателем 15 минут. Не оплатил - резерв снимается сам и товар снова в продаже.

Деньги списываем только после резерва: нельзя продать то, чего нет.

для предзаказа резерв ставится при поступлении

  • PaymentTimeoutException при оплате - норма, заказ уходит в orders-retry
  • статус в UI отстаёт до минуты: страница опрашивает API раз в минуту
Главное
Сначала резерв, потом оплата. Повторы гасит ключ идемпотентности, а склад и почта узнают об оплате из события order_paid.
API

Окно выдачи в столовой: сайт не лезет на кухню, а просит через окно, и ему выдают готовое.

Здесь это серверная часть магазина: принимает заказ от сайта и приложения, говорит со складом, оплатой и базой.

UI

То, что покупатель видит и нажимает: страницы, кнопки, формы.

Страница заказа сама спрашивает у API статус раз в минуту, поэтому может чуть отставать.

HPA

Автоматический найм: очередь растёт - выходят новые работники, спадает - уходят.

Механизм Kubernetes, который меняет число копий сервиса по нагрузке. Здесь он смотрит на длину очередей заказов.

B2B

Продажа компаниям, а не людям: оптом и по счёту.

Такие заказы приходят пачками через импорт, поэтому у них своя очередь orders-bulk и оплата по счёту, а не картой.

RabbitMQ

Почтовое отделение между сервисами: один кладёт письмо, другой забирает, когда освободится.

Хранит задачи в очередях, пока воркеры их не разберут. Если воркер упал, задача не теряется и уходит другому.

webhook

Платёжная система сама звонит магазину: "деньги пришли".

Это HTTP-запрос от внешнего сервиса на адрес магазина. Может не дойти, поэтому раз в час идёт сверка с банком.

Ключ идемпотентности

Номерок в гардеробе: сколько ни показывай его, пальто выдадут одно.

Уникальная строка, которую клиент шлёт с запросом. Сервер помнит её и на повтор отвечает тем же результатом, а не делает работу ещё раз.

at-least-once

Курьер гарантирует, что посылка дойдёт, но может принести её дважды.

Брокер не теряет события, но при сбоях повторяет их. Поэтому каждый слушатель проверяет, не обработал ли он это событие раньше.

order_paid

Объявление по громкой связи: "заказ такой-то оплачен", кому надо - реагирует.

Публикуется после webhook об оплате. Склад по нему собирает заказ, почта шлёт письмо.
